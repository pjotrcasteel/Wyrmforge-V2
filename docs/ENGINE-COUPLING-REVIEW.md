# Engine coupling review — 2026-11-18

Scope: static runtime imports and concrete ownership seams at baseline `4000e4a`, plus the R10-01 stone shortcut. WAT-10 `10664cd` was integrated after the review and changes only the fluid solver, adapter, mesh validation and their tests; no import edges change. This is not a proof of runtime isolation or an acceptance of every engine. Runtime source graph: 148 `.mjs` modules, 214 local import/re-export edges, no cycles. Existing dependency audit also checks repository isolation and V1 avoidance; it does **not** enforce engine ownership.

**Verdict:** core authorities are still separable; presentation and composition have accumulated coupling. We have crossed some intended boundaries and should clean the Lighting entry seams before adding its features. A rewrite of Voxel, WorldGen or Fluids is unwarranted.

| Area | Concrete evidence | Assessment / next action |
| --- | --- | --- |
| Voxel storage | `src/voxel-world.mjs` imports only microvoxel validation/constants. No art, browser or fluid dependency. | Healthy authority boundary. Preserve it. |
| Terrain port | `src/terrain-integration-port.mjs` owns query/command forwarding and committed notifications; consumer names include lighting and fluids. | Healthy integration direction. Consumers must unsubscribe and reject stale epoch/revision state. |
| Fluid solver | `src/fluid/column-fluid-engine.mjs` has no runtime imports; supplied floor query and immutable surface snapshots. `worldgen-fluid-adapter.mjs` reads the terrain port and subscribes to committed edits. | Healthy solver separation. Adapter currently reads whole-column `materialAt`, despite the port exposing `materialAtPoint`; partial microvoxel bank contact remains a semantic limitation. Concurrent Water work owns correction. |
| WorldGen | `src/world-generation/world-generator.mjs` supplies geometry and material intent; it references stable bedrock material identity, not WebGL or the fluid solver. | Correct direction. Recent cliff work changed geography in the visual workstream, but the implementation remained in WorldGen. Keep physical changes out of Materials. |
| Material definitions | `src/terrain-surface-library.mjs` and `terrain-texture-manifest.mjs` are data/validation, independent of GPU objects. | Healthy replacement seam for texture packs. Legacy asset key `stone/bedrock` also serves ordinary stone; identity 3 vs protected 4 remains distinct. Rename only with asset migration, not physics changes. |
| Shared terrain renderer | `src/webgl-voxel-view.mjs` imports Fire/Hunt/lab shader fragments and contains face lighting, normal response, height contrast and biome effects. 1,217 baseline lines. | Presentation is coupled to a particular Hunt/material pack. Before Lighting features, isolate material evaluation and light evaluation behind explicit hooks. Renderer owns GPU resources; Materials owns surface values; Lighting owns transport/occlusion. |
| Material shader reuse | `src/fire-terrain-material.mjs` reuses lab noise/helper definitions; stone shader relies on globals supplied by the assembled renderer. | Source-level shader ABI, not an engine-neutral contract. Make the required material inputs and output channels explicit at Lighting entry; avoid expanding lab dependencies. |
| Fluid presentation | `src/fluid/hunt-fluid-surface-renderer.mjs` includes its own lava/water palette and GL presentation, while `src/fire-lava-material.mjs` owns another molten palette/emission path. `hunt-fluid-surface.mjs` adapts into the older packed Hunt channel map. | Visual ownership is duplicated, solver ownership is not. Water stream retains solver authority; a later shared surface/emission contract should unify palette evaluation without moving the solver into Materials. Coordinate before editing these files. |
| Play Hunt host | `external-terrain-lab.mjs` is 2,291 baseline lines and composes camera, world, edits, actors, fluids, renderers, UI and diagnostics. | Central composition is expected; combined lab/game lifecycle and presentation policies make replacement expensive. Extract lifecycle/adapters incrementally when touched, not a broad rewrite during the fluid fix. |
| Object/physics dimensions | `src/hunt-woodland-objects.mjs` imports `ACTOR_HALF_WIDTH` / `ACTOR_HEIGHT` directly from terrain actor implementation. | Replaceable object collision is coupled to one actor shape. Later accept collider dimensions through the public movement/query context. |
| Structural support | `src/terrain-support-scan.mjs` reads parent `world.get`; partial occupancy can falsely bridge microvoxel gaps. | A semantic authority mismatch, already tracked as F07-04 #348. Generated overhangs stay off. Not fixed by material or lighting changes. |

## Recommended order

1. Obtain a new device performance report after the merged WAT-10 fluid correction and material shortcut. Material scope is frozen for now, not all performance issues closed.
2. Lighting entry: explicit surface/emission values and a light-evaluation hook; remove temporary lighting from material ownership without altering the visual baseline. Add narrow import/contract checks at this seam. Do not mark Lighting complete merely because these interfaces exist.
3. Implement a bounded lighting slice in the actual Hunt, then measure. Fluid palette unification and host decomposition can be separate follow-ups; micro-contact support remains a Voxel task.

No fluid, physics, WorldGen, actor, object or save-state implementation is changed by this wrap-up. No import cycles does not imply loose coupling: ambient shader globals, direct class assumptions, duplicate palettes and host lifecycle ownership are the main risks found here.
